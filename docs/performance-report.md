# รายงานประสิทธิภาพในเครื่อง

วัดเมื่อ 2026-10-04 หลังเพิ่มการเตือนในแอปและ migration รุ่น 6 ด้วย `npm run performance` โดยสร้าง SQLite ชั่วคราว 5,000 รายการ (ทุกลำดับที่ 20 ตั้งเตือนล่วงหน้า 7 วัน) เปิด Express บนพอร์ตสุ่ม และเรียกผ่าน HTTP loopback หลัง warm-up 1 ครั้ง สถานการณ์ละ 20 requests ขนาดหน้ารายการคงที่ 20 และศูนย์เตือนสูงสุด 50 รายการ

## สภาพแวดล้อม

- Windows `win32 x64`
- Node.js `v24.18.0`
- SQLite จาก `node:sqlite`
- เครื่อง local ใน workspace นี้; ไม่มี network ภายนอกในเส้นทางที่วัด

## ผลที่วัดได้

| สถานการณ์ | ต่ำสุด | Median | P95 | สูงสุด |
| --- | ---: | ---: | ---: | ---: |
| รายการหน้าแรก เรียงล่าสุด | 0.79 ms | 14.06 ms | 16.43 ms | 20.99 ms |
| ค้นหาชื่อและกรอง `DONE` พร้อมกัน | 2.22 ms | 15.19 ms | 17.91 ms | 18.48 ms |
| ศูนย์เตือนที่ถึงช่วงแล้ว | 3.74 ms | 15.42 ms | 17.00 ms | 17.11 ms |

API ใช้ `LIMIT 20 OFFSET ...` จึงแบ่งหน้าที่ backend และโหลด tags/subtasks ด้วย batch query แยกอย่างละหนึ่งครั้งแทน N+1 query ศูนย์เตือนใช้ partial index เฉพาะงานที่ยังไม่เสร็จและเปิดเตือน แล้วจำกัด 50 รายการ การค้นหา substring แบบ `%term%` ต้อง scan ชื่อบางส่วน; ที่ขนาดข้อมูลเป้าหมายยังไม่พบเหตุให้เพิ่ม cache หรือ search engine

ผลนี้ยืนยันเฉพาะ workload ผู้ใช้คนเดียวและ environment ข้างต้น ไม่ใช่หลักฐานรองรับผู้ใช้พร้อมกันจำนวนมากหรือ production traffic
